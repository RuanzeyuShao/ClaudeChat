# v0.1.4 会话内模型切换修复（2026-10-09）

版本保持 0.1.4。原 API、消息、附件、对话树、数据库表、迁移与 Usage 记录保留；本轮未修改 Git 标签或远端 Release。

## 修复结果

- 同一会话内应用 Claude、GPT、DeepSeek、Kimi、GLM、Grok、兼容服务的 API Profile、自定义模型、Thinking 和搜索配置，无需新建会话。
- 面板和 Composer 在生成中可打开并修改待应用草稿；“应用配置”保持禁用，当前请求使用独立快照。停止完成或生成结束后可以应用，随后发送的请求使用新配置。
- Composer 始终显示实际连接的 Provider 与模型；使用 Rust 返回的规范化配置，而不是仅显示客户端草稿。成功 Toast 包含 Provider 和模型。
- 每个会话保存完整连接选项及最后访问的会话 ID。重启恢复对应 Provider、Profile、模型、Thinking 和搜索，避免把历史会话模型与当前 Provider 错配。
- 配置、会话当前模型和会话连接快照在同一 SQLite 事务中提交；保存失败时客户端保持原配置、历史、引用、草稿和上下文筛选。后端在提交前检查 Profile、URL 与必要的系统凭据。
- 每次回答记录请求时的 Provider／Profile／模型／参数快照，和回答、Usage 一起原子保存；独立搜索模型的 Usage 也记录自己的来源。旧回答与费用不因切换、重命名或编辑 Profile 而被重写。
- 跨 Provider／模型的历史 reasoning 只在发送副本中隔离，数据库原文保留；图片、文档、引用与正文使用原有 Adapter 转换为目标协议格式。
- 流式事件携带请求 ID，旧请求的迟到正文、思考、来源和完成事件不能串入新回答；原 `chat-finished` 事件仍保留。新增 `requestId` 参数可省略，旧调用方式可继续使用。
- 修复 DeepSeek → GPT 时继承空 SearXNG 地址并自动启用搜索导致应用失败的问题；目标服务选择有效默认搜索服务，未配置 SearXNG 时草稿保持关闭。

## 实现边界

新增数据使用既有 settings 表中的 `v4:conversationConnection:<会话ID>`、`v4:lastConversation` 和 `v4:requestOrigins`，没有新增或重建表。API Key 不进入这些快照或前端持久化，仍使用系统凭据管理器。

旧版没有记录 Provider 的历史 Usage 不会被猜测或回填为当前 Provider；已有模型、Profile 名称、Token 与费用继续原样保留。新回复显示自己的请求来源。对于已删除的 Profile，历史仍可读取，恢复时停用不存在的连接，避免将请求发送到另一密钥。

记录的是本客户端实际请求的协议 Provider 和模型 ID；若网关内部改写模型或模型不支持某项能力，客户端不会伪造服务商的实际推理模型或能力。图片协议转换已验证，不等于所有模型都支持视觉。

- 四轮请求携带用户选择的自定义模型 ID，不使用 Profile 默认模型覆盖。
- 同一会话原节点、来源与文档保持原样，新增节点留在原树，旧分支仍可恢复。
- 历史文本、文档、图片转换成目标协议；跨模型 reasoning 副本隔离，存储原文保留。
- 输入／输出 Token 为服务返回的 7／4；各轮 model、Profile、费用与来源正确，旧费用记录 0.03 未改写。
- 会话快照恢复完整连接；事务故障同时回滚全局配置、会话模型、连接快照，回答来源保存失败则回滚回答与 Usage。

前端另测：生成中打开面板、当前请求参数深拷贝、停止完成前禁止切换、失败保留原状态、同 Profile 换模型、六个服务入口、后端规范化配置同步、重启不混用其他会话模型、历史标签不随当前模型变化、迟到事件隔离。

浏览器测试使用测试进程内存中的 Profile／历史样本，只验证真实运行的 Vue 交互；不将静态样本加入发布应用。未用个人 API Key 发起收费验收请求，未安装／卸载现有客户端。真实网关的鉴权、模型可用性和视觉能力仍由其实际响应决定。
