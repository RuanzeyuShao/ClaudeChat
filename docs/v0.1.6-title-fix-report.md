# v0.1.6 首轮 AI 标题兼容修正

2026-11-17。用户反馈型号为 `glm-5.2`，版本仍为 0.1.6。

## 排查与修正

- 标题请求曾使用 128 Token、15 秒总超时；GLM 的较慢响应可能超过该窗口，思考模型的预算还可能在正文前耗尽。
- 原生智谱 Adapter 已处理思考开关，但 OpenAI 兼容 Adapter 的 off 仅省略 reasoning_effort，未必关闭 GLM 默认思考。标题请求现在按 GLM 型号明确设置 thinking.type，兼容原生与兼容接入。
- 标题不继承聊天的附加生成参数，避免 enable_thinking、嵌套 extra_body、JSON、stop 等干扰标题。普通标题输出预算 256 Token，已识别推理模型 2048 Token；GLM-5.3 强制思考模型使用 low、4096 Token 上限。连接超时 15 秒、整个请求 60 秒，不增加自动重试。
- 兼容字符串与 text/output_text 分段返回；过滤独立 reasoning 和内嵌 think 内容，截断、未完成思考或纯思考返回不会被写成标题。接受兼容响应中的 error:null。
- 保留首次发送后后台生成、每个新会话只尝试一次、手动名称优先、失败不阻塞聊天、重启不重复、删除不复活。新版本不批量重试历史失败任务，以免额外计费；旧标题可手动重命名。
- 思考用量按 Provider 实际返回记录，仍属于 output 的子集，不重复加入费用。未改主聊天请求、界面、数据库结构和既有历史。

## 验证

TypeScript、110 项前端单元测试通过。Rust 覆盖七类协议、GLM-4.6/5.2 原生与兼容入口、分段正文、附加参数隔离、强制思考预算和用量、截断与思考内容过滤、只调用一次及失败不重试。

生产 WebView 使用独立 SQLite、本地模型 fixture 和 mock Key，验证首轮异步更新、追问/重生成/重启不重复、手动改名与删除竞态、失败不重试、附件摘要及 Usage；GLM fixture 额外等待 16 秒返回标题，验证超过旧超时窗口后仍能保存。未使用用户真实凭据或真实 GLM 配额，不能替代具体第三方中转服务的在线联调。

最终构建哈希和测试记录随修正版安装包放在 `installers/v0.1.6-title-fix/`。

## 协议依据

[Z.AI 思考模式](https://docs.z.ai/guides/capabilities/thinking-mode) 和 [深度思考参数](https://docs.z.ai/guides/capabilities/thinking)：GLM-5.2 支持关闭思考；GLM-5.3 不支持关闭，low 为低强度。实现只调整独立的标题请求，不改变用户聊天的思考设置。
