# ClaudeChat v0.1.4 长文本生成修复

日期：2026-10-14。版本保持 **0.1.4**。

## 根因与修复

1. Claude 原先默认正文预算约 4096 Token；增加为 8192 Token，Thinking 预算另行加入请求上限。用户显式设置的输出限制保持有效；旧网关拒绝较大默认值时兼容回退为 4096，并继续支持分段续写。
2. 识别 Claude 的 `stop_reason=max_tokens` 与 Chat Completions 的 `finish_reason=length`；达到上限后自动续写，并合并为同一条回答。每轮使用本次请求的原模型、API Profile、系统提示词、过滤后的上下文和附件。
3. 最多自动续写 8 次；无正文进展、上下文已满、服务商过滤／拒绝、用户停止或请求失败时不继续循环。未完成的回答明确显示原因及手动“继续生成”入口。
4. 自动续写仅第一段使用搜索配置；后续段落基于已获得的上下文继续回答，不额外启动搜索流程。搜索来源和执行事件仍保留。
5. 断线、缺少完成标记、错误流事件或续写请求失败时，保留此前已收到的正文、思考和来源，保存至 SQLite。原回答、分支和历史附件保留；重启后仍能查看生成结果及完成状态。
6. 接收到 `message_stop` / `[DONE]` 后及时结束，避免等待服务商继续保持的 HTTP 连接；没有明确完成标记时不再直接显示“已完成”。
7. 各段服务商返回的 Token 用量合并到此回答的 Usage 记录，保留原 Provider／Profile／模型归属。若某段未返回完整 Usage，明确标记为部分或未返回，不补造“实际 Token”。
8. OpenAI 配置中的 `max_tokens` 转换为当前 Chat Completions 的 `max_completion_tokens`；显式 `max_completion_tokens` 优先。自动续写保留用户的输出预算与其他请求参数。
9. 对续写开头与上一段末尾的较长精确重复片段做有限去重，避免流式显示和保存文本出现重复尾段；短词和常见标点保持原样。

## 行为与边界

- 自动续写会增加 API 调用，用量和估算费用合并记录；不会在会话树中添加内部续写提示词节点。
- 分段续写不能取消服务商的上下文窗口、账号限额或网关稳定性限制；这类情况保留已生成内容，并提供中断原因。续写上限为 8 次，仍未结束时可手动继续。
- 新完成状态使用既有 `v4:requestOrigins` 扩展持久化，数据库 schema 和历史数据格式不变。
- 现有消息发送参数保持不变；发送命令新增返回完成状态，同时保留流事件，旧调用方可继续忽略返回值。
- 本轮回归使用本地 HTTP 服务、隔离状态与临时 SQLite，不读取或改写用户实际聊天数据库，不消耗真实服务商 Token。

## 官方协议依据

- [Claude：处理停止原因](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)：流式读取 `message_delta` 的停止原因，输出预算耗尽不等于任务完成。
- [OpenAI 官方 API 文档：Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：输出预算字段及 `finish_reason`；`max_completion_tokens` 包含可见输出与推理 Token。
