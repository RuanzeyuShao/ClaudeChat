# v0.1.5 多配色主题实现与验证

日期：2026-10-15。版本保持 0.1.5。

## 使用

打开「设置 → 个性化」，用双色圆形色块切换经典翡翠、海洋蓝、紫罗兰、珊瑚橙、樱花粉、森林绿、琥珀金或石墨灰。悬停查看名称，当前项有勾选标记；方向键、Home、End 也可选择。外观模式独立选择浅色、深色或跟随系统。更改即时应用、自动保存，约 180 ms 过渡；系统减少动态效果设置可关闭过渡。

恢复默认回到经典翡翠、暖白背景和浅色模式，保留字体大小、连接、草稿、附件和历史。旧「通用偏好」外观入口继续可用。

## 实现与兼容

- `src/themes/themePresets.ts` 定义八套精确的浅色 Accent / Soft，以及独立调校的深色背景、侧栏、卡片、气泡、代码背景和强调色。通过统一 CSS Variables 切换，不复制主题 CSS。
- `accent-ink` 对文字进行对比度校正，`on-accent` 为填充按钮选择清晰的文字色；浅色 Accent 数值保持需求中的原值。图表副系列与强调色区分；Provider Logo 色、错误 / 警告 / 成功色保持独立。
- `themeManager` 在启动前应用外观缓存，SQLite 读取后以数据库为准；只管理主题颜色，不覆盖字体等 CSS 变量。单一媒体查询监听器实时响应系统外观变化，固定浅色 / 深色模式不受系统变化影响。
- `save_appearance` 命令只向已有 SQLite 设置表原子写入 `theme`、`color_theme`。白名单校验主题 ID，无需迁移或新增扩展键；老数据库缺省为经典翡翠，未知历史配色安全回退。
- 外观不加入连接身份或会话快照。切换主题不变更 Provider / Profile / 模型，不触发密钥操作或生成锁；快速点击依序保存，最新预览不会被旧响应覆盖，写入失败恢复最后一次成功保存的外观并显示错误。
- 控件、输入框、聊天气泡、选中历史、图表、文档预览和 Minimap 使用共享 Tokens。Minimap 继续保持默认 6 px、仅 Hover 18 px 的宽度逻辑。

## 验证范围

- 八套配色逐一检查浅色、深色、跟随系统共 24 组；每套跟随系统再模拟系统明暗实时变化。
- 浏览器覆盖设置页 / 输入 Focus、侧栏、聊天输入、用户气泡、代码块、发送按钮、Provider 面板 / Thinking、文档预览、对话树、非空用量图表及 Minimap 当前标记。
- 覆盖快速切换、键盘选色与焦点约束、页面重载、恢复默认、失败回退、草稿 / 字体 / 连接保留，以及 640×480 窗口在 100% / 150% / 200% 设备缩放下的布局。
- Rust 测试覆盖全部 24 组 SQLite 保存、旧配置回退、事务失败、历史切换和数据库关闭重开，验证已有消息保留。
- 实际生产 WebView 使用隔离的 APPDATA 和 SQLite，逐一通过真实 IPC 保存 24 组外观，并检查系统变化、进程重启恢复、恢复默认后再次重启、字体和草稿保留。不使用真实用户数据库，不调用模型服务。

## 检查结果

- Vitest：94 / 94 通过，其中主题专项 6 项。
- Windows Edge / Playwright：95 / 95 通过，其中主题专项 30 项，包含 24 组配色模式矩阵和原有引用、Minimap、附件、长输出、模型选择、用量统计回归。
- Rust：74 / 74 通过。环境使用 `NO_PROXY=127.0.0.1,localhost`，并以 `--test-threads=1` 避免本地协议测试的代理 / 并行干扰。
- TypeScript、Vite 生产构建、Windows x64 NSIS 构建通过；版本文件均保持 0.1.5。
- `node scripts/native-startup-smoke.mjs`：生产 EXE 的 8×3 主题、真实 SQLite 保存、系统变化、启动与两次进程重启、恢复默认、字体和草稿恢复检查通过。
- 主题设置截图保存在本地 `dist-release/v0.1.5/screenshots/themes/`，含各主题的三种模式；截图和浏览器结果未写入用户数据目录。

测试没有向真实服务商发出模型请求，也未在用户安装目录覆盖安装；原生测试运行的是与安装包相同构建的 Release EXE，使用独立临时数据目录。
