# v0.1.5 长回答自动续写与断点恢复

日期：2026-10-17。版本保持 0.1.5，继续使用已有 Vue / Tauri / SQLite 结构。

## 恢复规则

- `generation.rs` 统一管理调用状态。输出上限续写最多 8 次，可恢复错误另有最多 3 次自动恢复预算，两个计数在整次回答中分别有上限，不会因成功一段而重新获得恢复次数。
- 429（不含额度耗尽）、408、502、503、504、520、522、524、529、连接 / 读取 / 传输解码异常和没有终止标记的 SSE 结束可恢复。指数退避为 0.5、1、2 秒；数字 `Retry-After` 最多等待 30 秒，每 50 ms 检查停止。响应流和请求等待每 100 ms 检查停止，连接超时 20 秒、读取空闲超时 90 秒。
- 上下文超限、安全拒绝、权限 / 凭据错误、额度耗尽及其他不可恢复参数错误不会进行网络恢复。安全拒绝不提供续写入口。错误分类基于状态码、错误字段和 Provider 结束原因，不根据正常回答的措辞猜测安全状态。
- 正常 `stop` / `end_turn` / `stop_sequence` 和协议终止事件按正常完成处理，不按句末标点、长度或正则判断完整性。明确结束原因后为迟到用量保留最多约 1 秒收尾时间，网关不关闭连接也能正常结束。
- 无法自动恢复时显示「回答未完成」，保留正文、原因及继续入口；空回答可重试。正常回答的消息菜单提供用户主动触发的「检查并继续」，只发起用户要求的检查，不自动循环评估。

## 同一节点与断点

新回答建立一个稳定的 AI 节点。正文首次到达即可保存，随后有变化时约每 750 ms 保存检查点，轮次结束及最终状态再次保存。保存包含正文、Thinking、来源、搜索轨迹和生成状态；中途退出留下可识别的未完成状态，下次启动后可手动继续。强制终止可能丢失最后一个尚未落盘的时间片，不把尚未保存内容声称为已持久化。

自动续写和手动继续均携带原始任务、必要历史、累计回答和只用于请求的续写指令；这些辅助指令不写成用户消息。手动续写更新当前选中分支的末尾 AI 节点，不修改有后续消息的祖先；其他回答版本、附件和分支保持原样。跨模型继续时过滤请求中的外来 Thinking，已保存的 Thinking 不删除。

拼接只移除至少 32 字符的精确后缀 / 前缀重合（检查窗口 4096 字符），不通过猜测章节或正则重写回答。收到完全重复、没有新增正文的成功续写时，标记无进展并结束自动请求。模型仍可能生成语义重复的改写，客户端不擅自删除不能确认的内容。

## 来源与搜索

自动续写与恢复请求关闭搜索工具，优先复用已经取得的真实来源。来源标识、URL 和原生文本锚点一并保留；相同 URL 的不同引用别名不能合并重编号。请求中的来源上下文上限 64 项 / 16000 字符，标题和摘要有长度预算；未纳入上下文的来源卡片仍保留。

外部搜索在首次编号前做 HTTP(S) URL 去重与最多 24 项筛选，之后不再重编号。Kimi 的工具结果也可在后续网关故障时复用，不重新执行搜索。无法确认来源的论述继续沿用已有引用不可验证提示，不编造映射。

## 输出预算与调用统计

- 沿用 API Profile 的附加 JSON 配置，支持 `max_tokens` / `max_completion_tokens`，OpenAI 自动使用后者；不同时发送两个互相冲突的输出参数。
- 可设置仅客户端使用的 `client_max_output_tokens`，填写服务商确认的当前模型 / 网关上限。客户端取配置预算与此上限的较小值，此字段不会发送到 Provider。未知模型不根据名称猜上限，未知 OpenAI 兼容服务沿用服务商默认预算。
- Anthropic 仍有必需的默认输出预算与既有兼容处理，显式预算不被兼容回退覆盖；Thinking Budget 必须小于总输出预算，预算不足时下调或关闭 Thinking。参数仍被服务商拒绝时说明错误，不盲目放大预算。
- 已成功协商的 Thinking / stream_options / 默认输出限制在同次逻辑回答后续请求中复用，避免每段重复触发相同参数错误。
- 每个 API 调用独立创建 Usage 记录，包括 Kimi 工具轮次、自动恢复、手动继续和独立搜索模型。消息节点引用调用 ID 列表汇总显示，Dashboard 保留独立记录，不额外插入一个汇总记录造成重复计费。
- 以 Provider 报告的 Token 为准；中断未返回完整用量时，输出 / Thinking 可以按已收到文本估算并明确标识，输入未知则为不可用。零值不会伪装为已知实测值，费用是已有单价机制下的估算，不代表服务商最终账单。

## 验证

自动化包含所有七种协议适配（Anthropic、OpenAI、DeepSeek、Kimi、GLM、Grok、OpenAI 兼容），并覆盖输出耗尽、意外 EOF、真实传输截断、SSE 错误、429 / 502 / 503 / 504 / 524、上下文超限、内容安全过滤、额度与凭据错误、退避中停止、正常结束但连接悬挂、精确重复、无进展、续写失败及独立调用用量。

SQLite 测试验证同一节点重复保存、数据库重开、Thinking / 来源 / 轨迹与原分支保留、覆盖用户节点被拒绝和事务失败回滚。生产原生脚本使用隔离 APPDATA、真实 Rust IPC 与本地模拟 API，验证真实恢复、手动同节点追加、用量、强制退出和重启恢复，不读取或修改用户真实数据库和系统密钥。

- Windows Edge / Playwright：98 / 98 通过，包含三种窗口尺寸的长回答、继续后仍为两条消息、新恢复状态与停止按钮、旧引用与 Minimap、全部主题 / 模式、用量及模型切换回归。
- Rust：87 / 87 通过，包含所有七种适配的长度续写，以及上述断流、错误状态、计费来源、来源复用、参数复用和检查点用例。使用 `NO_PROXY=127.0.0.1,localhost` 与 `--test-threads=1`，避免本地模拟服务受系统代理影响。

- `node scripts/native-recovery-smoke.mjs` 在最终 Release EXE 中通过：真实 IPC / SQLite 自动恢复、独立调用用量、同节点手动继续、流式检查点、强制退出和进程重启后继续；独立搜索模型被安全拒绝时保留调用记录，并阻止后续回答请求。
