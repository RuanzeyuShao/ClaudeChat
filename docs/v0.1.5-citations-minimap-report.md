## 引用映射与位置

Markdown-it 使用专门的引用 token 处理连续 `[1][2]`、`[ref_1]`、原生唯一标识、`cite…`、`【ref_1†source】` 和有明确原网址的数字 Markdown 链接。代码、公式、普通链接与用户消息保持原有渲染。

引用的解析要求明确的来源 ID 或实际 Provider 注释，不能仅以来源数组顺序猜测。引用映射不代表客户端独立验证了来源内容对论述的事实支持；该支持关系来自 Provider 的标注或生成时明确提供的编号资料。无法确定来源或对应位置时，保留原始标号和位置，显示“引用不可验证”。旧历史没有保留来源编号时也遵循此规则。

只调整紧邻后置引用的句末标点，不越过文字移动引用。对于错误前置引用，只有 Provider 返回的答复文本范围在同一 Markdown 段落中有唯一、完整、可确认的句末匹配，才按该范围定位；重复文本、代码/链接内部、缺失范围、半句或歧义映射均不猜测。

- Claude：每个原生流式引用生成独立 ID，避免多个续写段落的局部数字互相覆盖；流式与最终正文使用同一映射。
- OpenAI：兼容嵌套和直接 `url_citation` 注释，保留合法字符范围对应的答复原文；不把原网页摘录误当作答复文本范围。
- GLM 等：保留 Provider 的显式 `refer` / `ref_id` / `citation_id` 标识；缺少映射时提示不可验证。
- Kimi：保留工具调用回显，给真实工具来源明确编号并将映射提供给下一轮模型；不依赖未经声明的数组顺序。
- SearXNG / 独立搜索模型：来源编号与实际放入模型上下文的编号一致，开始答复前发布对应来源。

来源快照随流式到达和自动续写合并，前端每条消息使用自身来源，不依赖当前切换到的模型配置。来源卡片保留原有去重与全部编号，点击卡片和上标复用安全网页打开逻辑。复制与导出将客户端内部引用 ID 转成可读数字，导出附上实际来源网址；不改变已保存正文。

`Source.anchor` 是 JSON 元数据的可选字段，旧历史缺省为无文本范围；不改变数据库 schema，不删除原历史。

## 历史导航轨道

`ConversationMinimap.vue` 位于聊天内容区域左边缘，为正文保留边距，轨道高度限定在消息滚动区域内，不覆盖侧栏和输入框。用户消息和助手消息使用不同长度的横线；只读取当前分支的 `active.messages`。

支持 Hover 摘要、点击最近消息标记、Pointer Capture 拖动、ArrowUp/Down 与 Home/End/PageUp/PageDown、当前阅读消息和视口范围高亮、折叠与本地记忆。短对话或隐藏的聊天页面自动隐藏。

标记统一绘制在一个 Canvas 中，没有每条消息的 DOM 或监听器。布局尺寸使用 ResizeObserver 合并测量，滚动使用 requestAnimationFrame 与二分定位，更新阅读位置时不重新绘制全部标记。流式文本变化不重建标记数据；测量实际 DOM，兼容消息高度变化、附件与分支切换。
