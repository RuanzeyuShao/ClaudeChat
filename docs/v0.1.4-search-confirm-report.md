## “Chat 内置搜索”与 SearXNG 的区别

原来的选项名称容易让人理解为“ClaudeChat 自带通用搜索”，实际含义是“调用当前 Provider API 的搜索工具”。它不登录或借用 Claude、ChatGPT 等网页端账号，也不会因为勾选就让普通模型具备搜索能力。

| 当前客户端适配器 | 实现方式与限制 |
| --- | --- |
| Claude / Anthropic compatible | Messages API 的 web_search 工具；API、模型、账号及中转站须支持 |
| OpenAI | Chat Completions 的 web_search_options，只能用受支持的搜索专用模型；普通 GPT 的 Responses 搜索工具是不同接口 |
| Kimi / Moonshot | 当前调用旧式 $web_search；并非所有新模型都支持，尚未实现 Formula 搜索 |
| GLM / Zhipu | Chat API 的 web_search 工具；仍需模型和 API 地址支持 |
| 通用 OpenAI compatible、DeepSeek、Grok | 本客户端当前路径未接入内置搜索；Grok 官方有专用搜索接口，但当前适配器未实现该接口 |
| SearXNG | 先由独立实例返回搜索资料和链接，再交给当前模型回答；可配合全部 Provider，但必须配置可访问且启用 JSON 搜索结果的实例 |

设置“默认搜索服务”只选择检索来源，还需在 Composer 选择“自动联网”或“始终联网”。现有“自动”逻辑在问题含问号、“搜索”或“最新”时启用；验证时可使用“始终联网”。选择原生搜索但没有来源，也可能是模型没有发起工具调用或网关没有返回工具结果，不能把单纯接受参数认定为已验证搜索。

官方依据：[Claude 搜索工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)、[OpenAI 搜索 API 与 Chat Completions 限制](https://developers.openai.com/api/docs/guides/tools-web-search)、[Grok 搜索接口](https://docs.x.ai/developers/tools/web-search)。实际客户端行为以 src-tauri/src/provider.rs 的适配器实现为准。

## 改动

- 通用偏好与模型面板统一显示“Provider API 内置搜索（需支持）”，禁用当前未接入的路径并显示按 Provider 区分的解释，不伪造能力状态。
- 搜索地址为空／格式错误、未实现的内置路径，在保存搜索连接或发送前检查；失败保留实际配置、输入草稿与附件，不先创建请求。
- Composer 的联网下拉框保存失败后恢复实际值；通用偏好与联网模式写入当前会话的现有连接快照，重开会话不会被旧搜索配置覆盖。
- 列表模型和自定义模型均选择后仅收起模型列表，配置界面保持打开，可继续修改思考和搜索。统一点击“应用配置”保存成功后关闭配置界面，更新实际标签和 Toast。失败保留草稿并显示错误；生成中只暂存选择，停止／结束后才能应用。当前交互详见 v0.1.4-model-list-report.md。
